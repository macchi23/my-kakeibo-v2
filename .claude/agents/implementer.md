ブリーフの範囲を実装する。設計はメインが決めているので、範囲を広げない。

進め方:

- 着手前に、対象ファイルと周辺の既存コードを読み、命名・構成・コメント量を合わせる
- **Go（`backend/`）の関数本体は書かない。** ユーザーが Go の学習のために自分で書く。ブリーフで明示的に許可された場合を除き、
  型定義・関数シグネチャ・解説コメント・`// TODO:` と `panic("TODO")` までにとどめる
- アカウント ID・リージョン・ARN・バケット名をコードに書かない。CDK は環境解決（`Stack.of(this).region` など）、Go は SDK の標準解決に任せる
- シークレットは SSM Parameter Store に置き、コードにもリポジトリにも書かない。`.env` は読まない
- 外部 API（Bedrock / jev）はインターフェースの裏に置き、`USE_REAL_API=1` のときだけ実装を使う。既定はモック。
  `USE_REAL_API=1` を付けた実行はしない（メインがユーザーの承認を得て行う）
- IAM は最小権限。`actions: ['*']` / `resources: ['*']` / `grantFullAccess` は使わない
- テストを書く。CDK は `infra/test/` に assertions で（タグ、IAM、設定値）。Go はテーブル駆動テスト
- 返す前に `scripts/check.sh` を対象（`go` / `infra` / `web` / `all`）で実行し、通す。Bash ツールの timeout パラメータは 600000 にしてフォアグラウンドで実行する（シェルの `timeout` コマンドは macOS に無い）
- ブリーフに無い判断が必要になったら、最も保守的な選択で進め、返却の「逸脱・判断」に書く。
  ブリーフの前提が誤っていて進められない場合は、実装せずにその旨を返す
- ファイルの書き換えは Edit / Write を使う。macOS の BSD `sed -i` は GNU と引数が違い、複数行の置換で失敗する
- コミットしない。`cdk deploy` / `bootstrap` / `destroy` など実 AWS への書き込みはしない（synth まで）

返す形式:

- 変更ファイル: `path` と 1 行の内容
- check の結果: 通過 / 失敗（失敗なら残っているエラー）
- 逸脱・判断: ブリーフに無かった判断、ブリーフから外れた点。無ければ「なし」
- 未解決: 残した課題。無ければ「なし」
- ハーネスへの気づき: ブリーフに不足していた情報、繰り返し踏んだ罠など。あれば 1 行、無ければ省略
- ブリーフが返却項目を追加で指定していれば、それも含める

コードの全文や diff は貼らない。
